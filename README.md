# 自适应 Goal 与循环编译器

**duke ｜ 联系与交流：微信公众号 Dukeland**

这是一个给 Codex `/goal` 和自主 Agent 写执行提示词的 Skill，适合需要持续推进、每做一轮才看得清下一步的大任务。你给它一个想完成的项目、已有材料和权限边界，它会把任务写成一段可交给 Agent 执行的 Goal。

做一款游戏，可以在开工时就决定要交出一章能从头玩到尾的试玩版。至于玩家会在哪个路口走丢，哪条任务路线的选择形同虚设，得等实际玩到那里才知道。这套方法把**本阶段要做到什么、凭什么验收、遇到不同问题该回到哪一步**写在 Goal 里，具体修法留到看见结果之后。能反复拿到新证据、又有空间根据证据调整做法的任务，才值得这么设计。

## 方法原理

### 把项目愿景落到一个可交付的阶段

「做一款有复杂任务和可探索城市的科幻 RPG」是项目愿景。当前这一轮可以约定交付一个完整首章，让玩家亲自走进街区、完成一项委托，再看到自己的选择怎样改变后续处境。这一章包含了游戏真正难做的部分。做成之后，才有一份可以据以决定如何扩大地图、增加任务和投入制作的成果。

确定这个阶段之前，Skill 会先看现有成品、规范、工具和失败记录。比如，已有原型能不能启动、能不能打包，决定了第一轮该沿着原型做，还是先验证运行条件。能用一次检查解决的就先查。只有目标、权限或质量取舍确实需要你拍板，才把问题留给你。设计完成后，执行者可以在授权范围内自行安排工作、换方法和修复问题。

### 用实际结果决定下一轮

同一款游戏里，「潜入路线进不了下一场」和「玩家走完了，却不知道自己的选择影响了谁」需要两种返工。前一种要查任务触发和状态，修完重走这条路线。后一种要看玩家在什么时候接到信息、做决定后看见了什么，可能需要改场景、对白或交互反馈，再让人玩一次。一个可运行的版本能同时暴露两类问题。

Skill 会先判断哪类证据最能决定任务是否做成，再设计主要的工作循环。一个项目可以同时有技术测试和成品审读，主要循环取决于最终交付要回答的问题。

| 工作循环 | 典型的阶段成果 | 哪种证据会改变下一步 |
| --- | --- | --- |
| 成品优化 | 把已有粗剪做成可试映的纪录片 | 试映者在哪一段误解了人物动机，决定要回去补哪段素材、重排哪一场 |
| 发现与选择 | 从多个产品机会里选出一个值得投入开发的方向 | 候选的试用和访谈结果决定淘汰谁，下一轮只给有希望的方向增加投入 |
| 研究与证伪 | 为下季度的技术投入作出有证据的路线判断 | 一个可信的反例或对照结果足以改变当前结论，就回去补实验或缩小结论范围 |
| 构建与验证 | 把一批历史档案做成可查询、能回到原件的资料库 | 真正的迁移、检索和回链检查暴露错配、遗漏或权限问题，定位后修规则并复跑 |
| 策略竞争 | 选定一种能持续做的栏目形态并做出首期 | 样刊的阅读反馈和实际制作投入决定哪个方向值得深化，完整首期还要再验一次 |

### 把过关的依据写清楚

写提示词前要想清楚，验收者实际看到什么、根据什么作判断、哪项问题足以否决交付。游戏可以用新存档和实际操作验证任务状态，用首次试玩验证玩家能否理解委托及其后果。研究要能沿着判断找到原始材料、实验记录和反证。代码和数据流程可以直接用构建、运行和核验结果裁决。约定好的验收要求贯穿各轮，执行者可以按新证据改变做法。

参照作品的用法取决于比较的目的。成熟商业游戏可以帮助说清想要的体验。要直接比较可玩质量，就用同阶段、同形态、同目的的试玩版。探索选题和策略时，过去的成品可以校准眼光，投入机会由眼下这批候选彼此竞争。确实需要独立评审时，让评审者看原始目标和实际成品，并确认运行环境和授权允许这样做。主 Agent 自己验收的结果按自审记录。

### 把验收和返工一起写进 Goal

最终提示词写明本阶段的一个主要目标、必读材料、硬边界、自主权限、工作循环、验收和停止条件。通常是 500～1500 个中文字符。把已经存在的设定、规范和测试用路径指给执行者，正文留给会改变它下一步行动的要求。浏览、运行、打包、调子代理等能力，都要按执行环境实际能做的事来写。

交付前，Skill 会预演两轮。第一轮试着按字面交差，例如给出能进街区的演示，却没有从接委托玩到看见后果。第二轮让这个结果接受验收，检查指令会不会推动 Agent 补上缺失的任务、重跑受影响的路线，并产出新版。Goal 同时写清怎么收口。达到约定的成果并完成验证即可交付，反复卡在同一个问题就换方法，关键输入或权限缺失时交出已完成的部分并说明缺口。

## 使用示例

下面三段是可以交给执行 Agent 的 Goal 示例。场景和材料均为假设，使用时换成你的项目条件。

### 做出一款赛博朋克 RPG 的可试玩首章

假设手上已有支持移动和对话的原型，想做一款原创的第一人称科幻 RPG。《赛博朋克 2077》提供的参照是可探索的街区，以及做出选择后，故事和周围人物真的会发生变化的体验。这个阶段要用一章完整的游戏验证这些东西能否一起成立。 [《赛博朋克 2077》官网](https://www.cyberpunk.net/us/en/cyberpunk-2077)

```text
把现有原型做成一份可单独运行、约 30～45 分钟的原创赛博朋克 RPG 首章。玩家从抵达港区进入主线，完成一项寻找失踪者的委托，看到自己选择的后果，最后抵达本章结局。读取项目的世界设定、原型操作说明、素材清单和打包要求。使用现有引擎和获准使用的素材，可自主调整任务、关卡、对白和实现，在项目环境内构建与打包。

先做通一条从新游戏到结局的可玩路线，再补出能够真正改变处境的另一种做法。玩家可以通过与街坊交涉取得线索，也可以潜入安保设施。让玩家能从街区布局、人物对白和现场动静里判断去哪儿、找谁。两条路线至少在一个后续场景产生可见的差异，例如某人是否愿意作证，或返程经过的街道是否被封锁。

每轮在可运行版本里检查受影响的路线。任务卡住就查触发条件和存档状态，修完复跑。路线都走通但选择的代价看不出来，就回到玩家接收信息或看到后果的场景，改完再体验。已有获准的首次试玩条件时，观察玩家能否自行完成委托，以及能否说清自己做了什么选择、后来发生了什么。只有开发者自测时，记录操作和实际观察，注明试玩反馈的来源。

交付前在打包版本中用新存档分别走完两条路线，核对结局和存读档之后的关键状态。交付试玩包、运行说明、两条路线的验证记录及需要玩家继续验证的问题。引擎、必要素材或测试条件确实阻塞时，交付已完成的部分和具体缺口。
```

### 用实验决定机器人团队下季度采哪种数据

假设一个团队有固定的抓取任务、测试环境、现有训练基线和少量两类数据。它要决定接下来的采集预算怎么投。能改变决定的证据，可能来自一次小规模训练，也可能来自发现之前的对照漏掉了真正难的场景。

```text
为项目中指定的机器人抓取任务，判断下季度的新增数据投入应优先用于真人遥操作示教、仿真数据，还是两者组合。交付一份能用于资源决策的报告和可复查的试验记录。先读任务定义、现有基线、数据清单、测试方案和算力预算。允许使用项目已有数据和实验环境做对照，新增采集和算力以现有授权为限。

从已有结果提出暂定判断，把可复核的研究材料用来找可能的失败条件。对照尽量使用相同的模型、任务、留出测试场景和成功判定，记录每条路线的数据成本与适用范围。先排查重复物体、相近场景泄漏、测试设置差异等会动摇判断的因素。条件不可比的结果，写清各自能说明什么。

优先验证能改变资源决定的疑点。如果一种数据在熟悉场景里占优，就检查它在留出物体或布局上是否仍成立。如果组合方案只有在投入更多数据或算力时领先，就尽量补做可比预算的对照。新结果改变判断时，更新推荐和适用条件，并把最有力的反证写进报告。

交付时说明推荐投入、支撑它的实验和来源、最可能使判断失效的条件。已有证据足以支持当前投入且关键反证已检查时收口。若决定仍取决于拿不到的数据或测试条件，就写出现在能确定的部分，以及哪项对照结果会改变预算分配。
```

### 把一个中文科技栏目做成值得连续投入的试刊

假设团队只能长期维护一个栏目，已有读者反馈和一批采访线索。它需要知道读者愿意为什么回来，以及编辑部能不能持续拿到材料。写出一篇好文章只能说明这一篇成立，接下来的选题和实际制作成本也要经得起检查。

```text
为现有读者群选定一档值得连续投入半年的中文科技栏目，并交付一份可送内部试读的完整首期。读取受众反馈、可用采访材料和编辑部的人手、工时及发布约束。可以自主找公开资料、筛选线索、制作样刊和修订稿件，在已有授权的范围内使用试读反馈。

找出几种读者会因不同理由持续关注的栏目方向。例如跟进一项技术进入工作现场之后的变化，或持续核查一类产品承诺在真实使用中的表现。先用真实线索检查每个方向能否反复找到足够具体、可查证的故事。为能成立的方向各做一份可以独立阅读的短样刊，用相近的制作投入和完成度给同一类读者比较。

有试读条件时，记录读者记住了什么、能否说出这档栏目每期会提供什么、愿意继续追哪类问题。结合从找材料到成稿的实际用时和下一批线索，选出一个方向做成完整首期。若读者喜欢样刊而后续素材难以获得，回到线索和栏目范围重做。若资料充足而读者说不清这档栏目为何值得读，改内容取舍或重新比较候选。

交付可试读的首期、选择依据，以及后续几期各自能找到的资料或采访线索。核对稿件事实和来源，并确认方向能在现有人手内继续做。如果这些条件还支撑不了长期投入，交出做过的样刊和导致暂缓的证据。
```

## 安装与使用

1. 下载或克隆本仓库。将 [`adaptive-goal-loop-designer/`](./adaptive-goal-loop-designer/) 整个目录复制到项目的 `.agents/skills/`，或个人的 `~/.agents/skills/`。如果列表里没出现，重启 Codex 后再查看。 [Codex Skills 文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)
2. 在对话里点名 `$adaptive-goal-loop-designer`，给它项目目标、现有成果的位置、可用工具和你已经定下的边界。有失败记录、验收样例或参考作品也可以一起给。普通聊天工具可以直接读取 [`SKILL.md`](./adaptive-goal-loop-designer/SKILL.md) 全文和任务说明来编写 Goal。
3. 把生成的完整提示词交给能访问材料的执行 Agent。支持 Goal 模式的 Codex 会话可以用 `/goal` 设置目标。其他环境可以直接发送提示词，实际能持续多久、能调用哪些工具，取决于该环境。 [Codex `/goal` 文档](https://learn.chatgpt.com/docs/reference/slash-commands#set-or-manage-a-goal-with-goal)
