# 自适应 Goal 与循环编译器

**duke ｜ 联系与交流：微信公众号 Dukeland**

这是一个为 Codex `/goal` 和自主 Agent 设计执行提示词的 Skill。你可以从一句还很模糊的想法出发，也可以给它一个已经做了一半的项目。它先找出会改变任务的未知，查到足以做决定，再锁定目标和边界。目标定下来之后，它才选工作循环、设计验收，并把这些决定写成一段能直接交给执行 Agent 的 Goal。

## 方法原理

### 1. 发现会改变任务的未知

「做一款类似《赛博朋克 2077》的游戏」，这句话还定不下要做什么。「类似」可能指可探索的城市、第一人称交互，也可能指玩家做过的选择会改变人物关系和后续任务。选哪一个作为核心，会改变交付物、技术投入和试玩时要观察的东西。项目到底已有可运行的原型，还是只有设定和美术参考，也会改变第一步。

Skill 从**目标、质量、方法、约束、验证**五个方面找这类缺口。它先读对话、规格、现有成品、基线和失败记录，再按未知的性质处理。

- 已经有答案的，直接沿用。例如项目说明已经定了引擎和目标平台。
- 知道缺什么且可以查的，自己核实。例如启动一次现有原型，确认能不能从编辑器运行、能不能独立打包。
- 有偏好但还说不清的，用案例、样例或小原型把它问具体。例如让人看两种委托玩法，确认其中哪些体验必须在首章里做出来。
- 连问题可能出在哪儿都不知道的，先做一次低成本试验。例如让两个最小任务共用存档，看看第一个任务留下的状态能否传到第二个。

确实会改变目标、质量取舍、范围或权限，而且需要你决定的事，才集中提问。查到足以决定成果、方法、验收和停止条件就可以收手。非关键的未知留给执行者在需要时核查。

### 2. 锁定目标与边界，给执行者留出自主空间

目标写清楚**最后交什么，成功之后实际发生什么变化**。边界还要交代可以改什么、必须保留什么、哪些事超出授权、要求冲突时保哪一项，以及谁凭什么验收。这一步也要核对材料和工具是否可用。

假设核实后定下的是「交付一个可独立试玩的港区首章，验证玩家的不同选择能否改变后续处境」。可以约定沿用已有引擎和获准素材，允许 Agent 调整任务、关卡和对白。当地图范围与任务体验冲突时，优先保住完整章节和两条有后果的路线。具体入口放在哪儿、任务状态怎么存，由 Agent 根据原型和测试结果决定。边界贯穿执行各轮，实施方法可以随新证据调整。

### 3. 按任务的成败依据选择一个主循环

Skill 原文称这一步为「任务拓扑路由」。它要判断这次是在改已有作品、挑值得投入的候选、查明一个判断、构建系统，还是选择并深化策略。**成功靠什么证据判定，失败后该去做什么**，这两个问题决定主循环。复杂项目可以有少量子循环。游戏首章的主循环可以是打磨可玩成品，任务触发和存档错误则用测试、修复、重跑的小循环解决。

| 主循环 | 一轮具体怎样做 | 适合的任务 |
| --- | --- | --- |
| 成品优化 | 改动成品，拿出可看或可玩的新版本。根据评审或同类成品的比较结果，定位缺陷并再改一版 | 把已有粗剪做成可试映的纪录片 |
| 发现与选择 | 扩大候选，用低成本证据筛掉站不住的选项。让现存候选竞争，只给有希望的加大投入，最后决定资源给谁 | 从一批产品机会里选出一个值得投入开发的方向 |
| 研究与证伪 | 提出暂定假设，主动找反例和替代解释，据此更新结论并再验证。结论有充分依据、关键反例已处理、未知范围已明确，且增查很难改变主要判断时收口 | 为下季度的机器人数据投入选路线 |
| 构建与验证 | 实现一版，运行测试、构建或数据校验。失败时定位根因，修复并重跑 | 把一批历史档案做成可查询、能回到原件的资料库 |
| 策略竞争 | 提出几种真正不同的方向，检验它们在受众、资源等现实条件下是否成立，让相关各方提出质疑。深化胜出的方向，再验收完整方案 | 为一个编辑部选定值得持续做的栏目形态并做出首期 |

### 4. 先设计验收，再写怎么做

原文的「评价装置」是一套具体的验收约定。验收者看哪个版本、看什么真实证据、谁有权判定、哪个问题足以决定过关、失败后回哪一步，都要先想清楚。游戏首章的裁决问题可以是「首次玩家能否自己走完委托，并说清做了什么选择、后来谁的态度变了」。任务走不通，回去查触发条件和状态。玩家走通却没看懂后果，回去改玩家接收信息的场景。下一轮需要拿出新版本再看，约定好的验收标准继续适用。

**标杆的用途要跟着任务变。** 同阶段、同形态、同目的的成品可以直接比较，例如可运行的试玩版对可运行的试玩版。做选题、创意和策略时，成熟作品和反例用来校准评审的尺度，同一批候选彼此竞争。做研究时，论文、报道和数据可以作为事实基线，帮助确认哪些已知、哪里还有待查的空间。测试、证伪或真实用户数据足以裁决时，可以直接用这些证据。

**独立评审只在任务确实需要时设为硬门槛。** 当任务风险或你的要求使独立评审成为必要条件，且环境允许时，把原始目标、成品、证据和必要的校准材料交给独立于生产者的评审者。评审先判是否通过，再给出决定成败的问题、根因、返工位置和重验方式。只有主 Agent 时，使用能运行的验证方式，自审按自审记录。

### 5. 核对运行条件，再把设计编成短指令

能不能持续执行、能否读写文件、运行测试或引擎、浏览页面、生成截图或可玩版本、调用独立代理，决定哪些机制能写进 Goal。只能本地运行的项目，就按可用的构建和验证方式设计。必要工具缺失会实质改变交付时，先说清缺的条件。

写 Prompt 时，已有的规格、设定和方法用文件路径引用。把正文留给会改变执行行为的决定，尤其是硬边界、验收证据、失败后要采取的动作和何时停下。Agent 可以在这些条件内拆解工作。同一个问题反复出现，就换一种调查或修复办法。关键输入或权限真的缺失，就交出能独立完成的部分，说明还差什么。

### 6. 交付前先预演两轮

第一轮，设想一个想尽快满足字面要求的 Agent 会交什么。比如它给出一张漂亮的港区截图，再附上一份分支剧情说明。第二轮，按验收规则判定这份交付，然后看 Prompt 会让它做什么。如果指令只能得到一份更详细的说明，设计还要改。对于这个游戏，第二轮应该去构建可运行版本，从新档走完两条路线，修掉实际卡住的任务，再验证后果有没有出现。这里预演和修订的是 **Goal Prompt**，实际试玩是执行阶段要做的验证。

## 交付格式

**还缺必须由你决定的条件时**，Skill 会说「在写 Goal Prompt 前，还需要你拍板 N 件会改变执行结构的事」，然后列出最少的必要问题。有真实取舍时给出选项、推荐和影响。能留到执行时查明的条件，直接写成运行时检查。

**条件齐备时**，Skill 的回复只有下面一句使用说明，加上**一个包含完整 Goal Prompt 的代码块**。

> 在执行 Agent 中输入 /goal，然后一次性粘贴下面整段；没有 /goal 的环境就直接粘贴发送。

代码块只保留七部分，通常 **500～1500 个中文字符**，复杂技术任务**最多 2200 个中文字符**。

| 七部分 | 写进去的内容 |
| --- | --- |
| 唯一目标 | 最终交付物和完成后可观察的变化 |
| 必读规格 | 执行者可以访问的规范、材料、基线和测试 |
| 3～5 条硬边界 | 范围、必须保留的条件及冲突时的优先级 |
| 自主权限 | Agent 可以自行决定和操作的事 |
| 主循环 | 根据哪种反馈继续做，失败后返回哪一步 |
| 评价装置 | 拿什么真实证据，由谁按什么标准验收 |
| 停止条件 | 达到什么状态交付，关键输入或权限卡住时怎么收口 |

找未知、比较路线和预演的记录留在设计过程中。最后交给执行者的是做成任务所需的指令。

## 使用示例

场景和材料均为假设，使用时换成你的项目条件。

### 做出一款赛博朋克 RPG 的可试玩首章

假设已经查清原型能运行、能打包，也确认这次最想验证街区探索和选择后果。把范围定在一个完整首章，采用成品优化作为主循环，用路线复跑检查任务状态，用试玩检查玩家是否感知到后果。《赛博朋克 2077》用来说明期望的体验。 [《赛博朋克 2077》官网](https://www.cyberpunk.net/us/en/cyberpunk-2077)

> 在执行 Agent 中输入 /goal，然后一次性粘贴下面整段；没有 /goal 的环境就直接粘贴发送。

```text
目标
把现有原型做成可独立运行、约 30～45 分钟的原创赛博朋克 RPG 首章。玩家抵达港区，完成寻找失踪者的委托，看到自己选择的后果，并玩到本章结局。

必读规格
读取项目的世界设定、原型操作说明、素材清单和打包要求。

硬边界
- 使用项目现有引擎、目标平台和获准素材。
- 交涉和潜入两条路线都须能通关，至少在一个后续场景产生可见差异。
- 地图范围与任务体验有冲突时，优先保住完整章节和选择后果。

自主权限
可自主调整任务、关卡、对白和技术实现，并在项目环境内构建、测试和打包。

主循环
先接通从新游戏到结局的一条可玩路线，再补足另一条路线及其后果。每轮拿出可运行版本并检查受影响的部分。路线卡住时修触发条件或状态，改完复跑。玩家选了不同办法却看不出后果时，改玩家收到信息或见到变化的场景，再体验。例如玩家可以从街坊处取得线索，也可以潜入安保设施，选择会改变证人是否愿意作证，或返程的街道是否被封锁。

评价装置
在打包版本中用新存档分别走完两条路线，核对后续差异、结局及存读档后的关键状态。能安排获准的首次试玩时，看玩家是否能独自完成委托，并说清选择与后果。开发者自己走的路线按自测记录。

停止条件
完成首章并通过约定验证后，交付试玩包、运行说明、两条路线的验证记录及待试玩的问题。引擎、必要素材或测试条件确实阻塞时，交付已完成的部分并说明缺口。
```

### 用实验决定机器人团队下季度采哪种数据

假设一个团队有固定的抓取任务、测试环境、现有训练基线和少量两类数据。它要决定接下来的采集预算怎么投。能改变决定的证据，可能来自一次小规模训练，也可能来自发现之前的对照漏掉了真正难的场景。

```text
目标
为项目指定的机器人抓取任务，判断下季度新增数据投入应优先用于真人遥操作示教、仿真数据，还是两者组合，形成可复核的资源决策依据。

必读规格
读取任务定义、现有基线、数据清单、测试方案和算力预算。

硬边界
- 建议限定于指定任务及证据覆盖的场景。
- 数据、采集和算力以项目现有授权为限。
- 直接对照采用可比的模型、留出测试场景和成功判定，条件不同的结果注明差异。

自主权限
可以查可核实的研究材料，运行现有实验流程，并在预算内补做最能改变决定的对照。

主循环
从已有结果提出暂定判断，找反例和可能的替代解释，再做对照。先查重复物体、相近场景泄漏和测试设置差异。若某类数据只在熟悉场景占优，就检查留出物体或布局。若组合方案在更多数据或算力下领先，就补做可比预算的对照。新证据改变判断时，更新推荐和适用条件。

评价装置
用留出场景的成功率、实际投入、失败记录和来源来检查推荐能否成立。每项关键结论都要能追到支持它的记录，同时写出最有力的反例或替代解释，以及它是否改变预算分配。

停止条件
证据足以支持当前投入、关键反证已处理、新调查对主要判断影响很小时，交付建议、试验记录和适用条件。仍缺能决定预算的证据时，交出可确认的部分，说明需要哪项对照及什么结果会改变判断。
```

### 把一个中文科技栏目做成值得连续投入的试刊

假设团队只能长期维护一个栏目，已有读者反馈和一批采访线索。它需要知道读者愿意为什么回来，以及编辑部能不能持续拿到材料。写出一篇好文章只能说明这一篇成立，接下来的选题和实际制作成本也要经得起检查。

```text
目标
为现有读者群选定一档值得连续投入半年的中文科技栏目，并交付可送内部试读的完整首期。

必读规格
读取受众反馈、采访材料、编辑部的人手、工时及发布约束。

硬边界
- 栏目应能在现有人手和工时内持续制作。
- 样刊用相近的制作投入和完成度给同一类读者比较。
- 稿件的核心事实能追到来源，试读在已有授权范围内进行。

自主权限
可以自主找公开资料、筛选线索、制作样刊和修改稿件。

主循环
找出几种读者会因不同理由持续关注的方向，例如跟进技术进入工作现场之后的变化，或长期核查一类产品承诺在真实使用中的表现。先用线索筛选哪些方向能反复找到可查证的故事，再做可独立阅读的短样刊。选定方向后做成完整首期，核对事实和来源。若读者喜欢而后续材料难找，回到线索和栏目范围。若材料充足而读者说不清每期值得读什么，改内容取舍或重新比较候选。

评价装置
结合试读者实际记住的内容、愿意继续追的问题、制作一期的实际工时和下一批线索，判断只有一档栏目能获得投入时选谁。用同样的条件回看完整首期，确认方向在现有人手内做得下去。

停止条件
方向成立并完成首期核验后，交付可试读的首期、选择依据和后续几期各自的资料线索。若关键条件还支撑不了长期投入，交出已做的样刊和导致暂缓的证据。
```

## 安装与使用

1. 下载或克隆本仓库。将 [`adaptive-goal-loop-designer/`](./adaptive-goal-loop-designer/) 整个目录复制到项目的 `.agents/skills/`，或个人的 `~/.agents/skills/`。如果列表里没出现，重启 Codex 后再查看。 [Codex Skills 文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)
2. 在对话里点名 `$adaptive-goal-loop-designer`，说说你想完成的事。有现成的规格、原型、失败记录、参考作品或已定的边界，就一起给它。普通聊天工具可以直接读取 [`SKILL.md`](./adaptive-goal-loop-designer/SKILL.md) 全文和任务说明来编写 Goal。
3. 把生成的完整提示词交给能访问材料的执行 Agent。支持 Goal 模式的 Codex 会话可以用 `/goal` 设置目标。其他环境可以直接发送提示词，实际能持续多久、能调用哪些工具，取决于该环境。 [Codex `/goal` 文档](https://learn.chatgpt.com/docs/reference/slash-commands#set-or-manage-a-goal-with-goal)
